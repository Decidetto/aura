## 2. Детальный разбор и руководство к действию

### 🔴 Приоритет P0: Критические блокеры

#### 1. K1 — Сайт и релизные манифесты
* **Где:** `website/index.html` (строки 55, 80, 505), `website/index_ru.html` (строки 52, 77, 502), `release-manifest-1.0.9.json`.
* **Суть проблемы:** Ссылки переключены на `Aura_1.0.9_x64-setup.exe`, но в `website/` лежит только бинарник `Aura_1.0.8_x64-setup.exe`. Манифест 1.0.9 содержит фиктивные хеши.
* **Причина:** Преждевременное обновление версий в HTML до компиляции и выкладывания финального билда v1.0.9.
* **Что делать:**
  1. Либо собрать и выложить реальный `Aura_1.0.9_x64-setup.exe` в `website/` и пересчитать SHA-256.
  2. Либо (если 1.0.9 еще тестируется) вернуть ссылки в HTML на `Aura_1.0.8_x64-setup.exe`.

#### 2. K2 — Приватность: сырой текст в логах Hugging Face
* **Где:** `src-tauri/src/ai_client.rs` (строки 691–696).
* **Код:**
  ```rust
  crate::logger::log(
      "INFO",
      "LLM",
      None,
      &format!(
          "Executing Hugging Face context editing for selected text ({} chars, prompt: \"{}\")...",
          selected_text.chars().count(),
          transcribed_text
      ),
  );
  ```
* **Суть проблемы:** Санитайзер в `src-tauri/src/logger.rs:280–301` ищет только строку `"Final result: "`. При включении Hugging Face и генерации отчета об ошибках текст пользователя попадает в диагностический лог даже при `log_speech_text = false`.
* **Что делать:** Заменить логирование сырого текста на количество символов/слов:
  ```rust
  &format!("Executing Hugging Face context editing for selected text ({} chars, prompt: {} chars)...",
      selected_text.chars().count(),
      transcribed_text.chars().count()
  )
  ```

#### 3. K3 — ReferenceError при смене языка UI
* **Где:** `src/main.js:1885–1889`, `src/index.html:86`.
* **Суть проблемы:** Функция `updateSelectPreview` была удалена в прошлом рефакторинге, но глобальный слушатель остался. При изменении языка интерфейса бросается исключение `ReferenceError`.
* **Что делать:** Удалить неиспользуемый слушатель `updateSelectPreview` из `src/main.js` и убрать атрибут `data-preview` из тега селектора в `src/index.html`.

### 🟠 Приоритет P1: Быстрые победы (Скорость и Стабильность)

#### 1. Оптимизация VAD: Слияние гейта и тримминга в один проход
* **Где:** `src-tauri/src/lib.rs:3262–3283` и `src-tauri/src/vad.rs`.
* **Суть проблемы:** Сейчас файл WAV считывается с диска дважды: сначала в `vad::wav_has_speech`, затем в `vad::trim_wav_file`. Нейросетевой детектор Silero VAD также запускается два раза на одних и тех же аудиосэмплах.
* **Что делать:** Реализовать функцию `vad::process_and_trim_wav(path: &str) -> Result<VadOutcome, String>`, которая читает файл 1 раз, прогоняет через Silero 1 раз и, если речь есть, сразу сохраняет обрезанный WAV. Это экономит **100–300 мс** на каждой батч-транскрибации.

#### 2. Устранение искусственной задержки `sleep(1400ms)`
* **Где:** `src-tauri/src/lib.rs:3372`.
* **Суть проблемы:** При переключении с недоступного облака на локальную модель поток транскрибации засыпает на 1.4 секунды только для того, чтобы оверлей успел отобразить уведомление. Текст вставляется пользователю с полуторасекундной задержкой.
* **Что делать:** Убрать `tokio::time::sleep`. Уведомление оверлея (`app_handle.emit("recording-state", "notice:...")`) отправляется асинхронно, а текст должен печататься сразу.

#### 3. Асинхронная запись истории (DPAPI)
* **Где:** `src-tauri/src/lib.rs:3435–3451`.
* **Суть проблемы:** `history::add_entry` синхронно шифрует строку через Windows DPAPI и пишет в базу SQLite прямо перед `keyboard_simulator::paste_text`.
* **Что делать:** Перенести сохранение в историю **после** завершения вставки текста (`paste_text` / `type_streaming_update`) либо обернуть в неблокирующий `tokio::task::spawn_blocking`.

#### 4. В1 — Устранение гонки автосохранения настроек
* **Где:** `src/main.js:2467–2545`.
* **Суть проблемы:** Если пользователь изменил инпут во время летящего `saveSettings()`, запрос игнорируется (`saveInFlight = true`), а при завершении `settingsModified` безусловно сбрасывается в `false`. Изменение теряется.
* **Что делать:** Добавить флаг `hasPendingModifications`: если во время сохранения произошли изменения, в секции `finally` вызвать `saveSettings()` повторно через debounce.

#### 5. В2 / В3 — Fail-fast для облачных провайдеров и общий тайм-аут
* **Где:** `src-tauri/src/ai_client.rs:534–615` и `src-tauri/src/lib.rs`.
* **Суть проблемы:** При неверном ключе (401) или 400 Bad Request каскад перебирает все 6 моделей Gemini, отправляя 25 МБ аудио в каждую. Таймаут клиента 900 с может подвесить процесс на минуты.
* **Что делать:**
  - При статусах 400, 401, 403 делать мгновенный `return Err(...)` (Fail-fast) без перебора остальных моделей.
  - На уровне `lib.rs` обернуть вызов облачной транскрибации в общий лимит времени `tokio::time::timeout(Duration::from_secs(30), ...)`.

### 🟡 Приоритет P2: Надежность, Edge-cases и Полировка

#### 1. В4 — Watchdog и прогрев для `whisper-server`
* **Контекст:** Для `Parakeet` написан `ParakeetWatchdog`, который перезапускает упавший процесс и держит сокет прогретым. `whisper-server` сейчас опирается только на проверку перед запросом и CLI-фолбэк.
* **Решение:** Зеркалировать логику watchdog на `whisper-server`, чтобы резидентный HTTP C++ процесс автоматически восстанавливался в фоне.

#### 2. В5 — Информирование о блокировке UIPI (Окна Администратора)
* **Контекст:** Процесс без прав администратора не может передавать ввод в окна с повышенными привилегиями (защита Windows UIPI). `SendInput` возвращает 0.
* **Решение:** Проверять возвращаемое значение `SendInput`. Если результат 0 и `GetLastError() == ERROR_ACCESS_DENIED`, логировать предупреждение и показывать пользователю оверлей: *«Целевое приложение запущено от имени Администратора»*.

#### 3. В9 — Защита от смены хоткея во время активной сессии
* **Где:** `src-tauri/src/keyboard_hook.rs:268–276`.
* **Решение:** В `update_hotkey` проверять `SHORTCUT_ACTIVE.load(...)`. Если запись идет прямо сейчас, возвращать ошибку `Err("Cannot update hotkey while recording is active")` либо откладывать смену до события `KeyUp`.

#### 4. В12 — Автоматический выбор скачанной модели
* **Где:** `src/main.js:2617–2620`.
* **Суть:** Если во время длительного скачивания модели А пользователь переключился на модель Б, по окончании загрузки вызывается `selectModelCard(model)`, сбрасывая выбор пользователя.
* **Решение:** Запоминать, какую карточку выбрал пользователь, и не переключать ее принудительно, если фокус был смещен.

## 3. Разбор решений: что сделано специально

1. **Очистка галлюцинаций в `text_normalizer.rs`:**
   * Аудитор отметил, что фильтр удаляет строки вроде «Конец!», «Перевод: ...».
   * **Почему это сделано:** Модели Whisper на участках тишины генерируют галлюцинации из метаданных YouTube (*«Субтитры создавал...»*, *«Конец фильма»*, *«Спасибо за просмотр»*). Фильтр был добавлен именно для защиты от этого мусора.
   * **Как улучшить:** Не удалять жестко слово «Конец», а проверять длину записи или наличие других слов в предложении.

2. **Монолитная загрузка CUDA-рантайма (В7):**
   * Аудитор предложил пофайловый resume для 500 МБ CUDA-архива.
   * **Почему так:** CUDA-библиотеки распространяются как единый архив с жестким SHA-256. В отличие от языковых моделей, которые пользователь может докачивать по отдельности, CUDA ставится один раз. Добавление resume приветствуется, но отсутствие докачки не являлось багом.
